# Prime Number Generator

A C++ console program for generating and testing prime numbers up to 32 bits. It implements two methods for finding primes: naive trial division and the Miller-Rabin test.

The program also includes a few tests for comparing their execution times and checking the distribution of numbers generated by an LCG. It was made as part of a master's degree course. The program's menu is in Slovene.

## Building and running

The program is a single source file and only uses the standard library. Any compiler with C++11 support will do:

```
g++ -O2 -std=c++11 main.cpp -o prime_generator
./prime_generator
```

On Windows the executable is `prime_generator.exe`. The CSV files are written to the directory you run the program from.


## Menu

| Option | What it does |
|--------|--------------|
| 1 | Generate a prime with the naive method. Asks for the number of bits (2 to 32). |
| 2 | Generate a probable prime with Miller-Rabin. Asks for the number of bits (2 to 32) and the parameter `s`. |
| 3 | Check whether a number (up to 32 bits) is prime using trial division. |
| 4 | Check whether a number (up to 32 bits) is probably prime using Miller-Rabin. Asks for `s`. |
| 5 | Test the random number generator and write a histogram to `histogram.csv`. |
| 6 | Time both generators for 4 to 32 bits and write `timing.csv`. |
| 7 | Time the Miller-Rabin generator for `s` from 1 to 20 and write `timing_s.csv`. |
| 0 | Exit. |

## How it works

### Random number generator

The program uses its own linear congruential generator (LCG):

```
R(n+1) = (69069 * R(n) + 1) mod 2^32
```

The seed defaults to 0, so every run of the program produces the same sequence. That is on purpose, it makes the results reproducible. To get a number in a range `[x, y]` the generator returns `x + next() % (y - x + 1)`.

### Generating a prime

Both generators work the same way. A random starting number is picked in the range `[2^(bits-1), 2^bits - 1]`, which guarantees the result has exactly the requested number of bits. If the number is even it is moved to the next odd one. Then the candidate is tested, and if it fails the program moves on by 2 and tries again. If the candidate goes past the top of the range it wraps around to the bottom.

The only difference between the two generators is the primality test they call.

### Naive test

Trial division. It rejects even numbers and then tries every odd divisor from 3 up to the square root of the candidate. This is always correct but the number of steps grows with the square root of the input, so it gets slow as the bit count goes up.

### Miller-Rabin test

A probabilistic test. It writes `p - 1 = 2^k * d` with `d` odd, then repeats `s` times: pick a random base `a` in `[2, p - 2]`, compute `a^d mod p` using square-and-multiply, and check whether the result is a witness that `p` is composite. If any round finds a witness the number is definitely composite. If all `s` rounds pass, the number is declared probably prime.

A composite number gets through a single round with probability at most 1/4, so the chance of a wrong answer after `s` rounds is at most 4^(-s). With `s = 10` that is below one in a million.

### Why 32 bits

All arithmetic is done in `unsigned long long` (64 bits). Squaring a 32-bit number fits in 64 bits, so `(x * x) % p` never overflows. Going above 32 bits would need 128-bit multiplication or a big integer library.

## Tests and output files

**Option 5, LCG test.** Draws 1,000,000 numbers in the range 1 to 1000 and counts how often each one appears. The counts go to `histogram.csv` (columns `Number`, `Frequency`). For a good generator the histogram should be roughly flat at about 1000 per number.

**Option 6, bits vs. time.** For every bit size from 4 to 32, runs each generator 100 times (Miller-Rabin with `s = 10`) and records the average time. Output is `timing.csv` with the columns `Bits`, `Naive_ns`, `MillerRabin_ns`. Times are in nanoseconds. The naive curve grows much faster, so a logarithmic Y axis makes the chart easier to read.

**Option 7, `s` vs. time.** Generates a 32-bit prime with Miller-Rabin 1000 times for each `s` from 1 to 20 and records the average. Output is `timing_s.csv` with the columns `s`, `MillerRabin_ns`. The time should rise roughly linearly with `s`.

Both timing functions take the generator by value, so they work on a copy and always start from the same state. Running them does not change the generator used by the other menu options.
